# Продуктовая ошибка GenAI компаний: pay-as-you-go убивает рост

**Автор:** независимый продуктовый менеджер (Хабр, май 2026)  
**Хабр:** https://habr.com/ru/articles/1026722/  
**GitHub:** не применимо (стратегический анализ)  
**Слой:** orchestration / analytics  
**Дата:** май 2026  
**Уникальность:** Системный разбор почему большинство GenAI компаний совершают одну и ту же продуктовую ошибку: модель pay-as-you-go создаёт неверные стимулы — провайдер зарабатывает на вычислениях, пользователь хочет экономить. Альтернатива: value-based monetization + результато-ориентированные контракты. Применимо к любому AI-продукту.

## Суть ошибки: pay-as-you-go = конфликт интересов

```
Модель pay-as-you-go (как у всех крупных LLM-провайдеров):
  Провайдер зарабатывает → чем БОЛЬШЕ токенов использует клиент
  Клиент хочет → использовать как можно МЕНЬШЕ токенов

Конфликт интересов:
  Провайдер: "сделай запросы длиннее, добавь context, включи CoT"
  Клиент: "как мне сократить расходы на AI?"

Следствие:
  → Клиент воспринимает AI как "расход", а не "инвестицию"
  → Использует AI меньше, чем мог бы
  → ROI кажется низким
  → Churns (уходит)
```

## Альтернатива: value-based monetization

```python
# Модель 1: Outcome-based (по результату)

# Вместо: "заплати $3 за 1M токенов"
# Предложить: "заплати $X за каждый обработанный договор"

contract_analysis_pricing = {
    "unit": "один договор",
    "price": 150,  # рублей
    "клиент видит": "за 150₽ я получаю полный анализ рисков",
    "vs_traditional": "юрист берёт 5000-15000₽ за тот же договор"
}

# Психология: клиент считает экономию (5000 - 150 = 4850₽ saved)
#              а не токены (150₽ vs "сколько это токенов?")


# Модель 2: Subscription (плоская плата)

subscription_model = {
    "plan": "Business",
    "price": "49,900₽/месяц",
    "includes": "до 500 документов + неограниченные вопросы",
    "психология": "AI = постоянный сотрудник за 49,900₽/мес",
    "vs_традиционный_сотрудник": "джун-аналитик стоит 80-120K₽/мес"
}

# Клиент сравнивает с зарплатой, не с облачными расходами
# → AI выглядит дёшево и ценно одновременно
```

## Семь паттернов GenAI монетизации

```
1. TOKEN-BASED (ошибочный):
   Зарабатываем на вычислениях → конфликт интересов
   Пример: OpenAI API, Anthropic API, Azure OpenAI
   Для кого подходит: только для инфраструктурных провайдеров

2. OUTCOME-BASED (правильный для вертикальных SaaS):
   Зарабатываем за результат → интересы совпадают
   Пример: "за каждый обработанный документ", "за каждый скрин сделку"
   Для кого: legal tech, fintech, HR tech

3. SUBSCRIPTION + FAIR USE:
   Плоская плата + лимиты → предсказуемо для обеих сторон
   Пример: Notion AI, GitHub Copilot
   Для кого: productivity tools, developer tools

4. FREEMIUM → PREMIUM:
   Базовое бесплатно → платно за advanced
   Ловушка: если AI в premium = основная ценность, free привлекает не тех
   Пример: Jasper AI, Grammarly
   Для кого: consumer apps с viral loop

5. PLATFORM + MARKETPLACE:
   Зарабатываем на экосистеме, AI = компонент
   Пример: Salesforce Einstein, HubSpot AI
   Для кого: platform players с lock-in

6. USAGE + SUCCESS FEE:
   Базовая подписка + % от сэкономленного
   Самый честный alignment: чем больше сэкономили клиенту → больше заработали
   Пример: редко используется, но растёт

7. DATA FLYWHEEL:
   AI бесплатно в обмен на данные для улучшения модели
   Работает только для платформ с сетевым эффектом
   Пример: early Google, OpenAI Chat
```

## Почему wrapper-стартапы умирают

```
Типичный GenAI wrapper:
  Берёт Claude/GPT API → добавляет UI → продаёт как SaaS
  Первые 6 месяцев: растёт (early adopters)
  Затем: умирает

Причины смерти:
  1. Anthropic/OpenAI выпускает такую же фичу нативно
  2. Клиенты уходят напрямую в API (дешевле)
  3. Нет defensibility: конкурент делает то же самое за неделю

Что выживает:
  → Вертикальная специализация (только для юристов/логистов/HR)
  → Собственные данные (уникальный обучающий набор)
  → Сетевые эффекты (ценность растёт с числом пользователей)
  → Глубокая интеграция с существующими системами (1С, CRM, ERP)
```

## Российский рынок: специфика

```
Уникальные возможности для RU GenAI B2B:

1. Локальные данные:
   → OpenAI не обучает на специфике ГК РФ, ФЗ-152, налоговом кодексе
   → Нишевая fine-tuning на русском праве = defensibility

2. On-premise demand:
   → ФЗ-152, банковское регулирование, гостайна
   → Клиенты ГОТОВЫ платить за self-hosted решение
   → Примеры: Directum, 1С с AI-плагинами

3. Интеграция с российским стеком:
   → 1С + AI = огромный рынок (1С у всех)
   → Мой Офис, Яндекс 360 + AI = альтернатива Google Workspace

4. Импортозамещение:
   → После 2022: спрос на RU-аналоги с AI
   → Государство финансирует через РФРИТ, Сколково гранты
```

## Возможные комбинации

| Комбинация | Новое свойство |
|------------|----------------|
| **GenAI Product + LLM Router (R20)** | Router = операционная модель: дешёвые модели → unit economics работают |
| **GenAI Product + Jay Guard (R21)** | Privacy-first продукт = defensibility для корпоративного B2B |
| **GenAI Product + Self-hosted (R22)** | Self-hosted = on-premise pricing модель: не tokensам а лицензия |
| **GenAI Product + Fine-tuning (R15)** | Вертикальная специализация через fine-tuning = defensibility |
| **GenAI Product + Data Flywheel** | Каждый клиент → данные → лучшая модель → больше клиентов (network effect) |
