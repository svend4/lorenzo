## Ключевые тезисы

### Что такое контекст агента

```
Контекст агента (100%):
├── System prompt                    ~30%
├── CLAUDE.md / Rules / Memory       ~25%
├── MCP tool results                 ~20%
├── History / previous turns         ~20%
├── Skills / snippets                ~ 5%
└── Ваш текст (промпт)              ~0.03%
```

### Почему caching критичен

> 95–96% всех input-токенов в типичном агентном цикле — **cache reads**.  
> Без кэширования агентные циклы экономически убыточны.

### Context Engineering vs. Prompt Engineering

| Аспект | Prompt Engineering | Context Engineering |
|--------|-------------------|---------------------|
| Фокус | Формулировка запроса | Архитектура контекста |
| Инструменты | Руки + интуиция | CLAUDE.md, MCP, memory |
| Масштаб | Один запрос | Весь агентный цикл |
| Экономика | Не важна | Кэш = ключевой фактор |

## Практические компоненты

1. **CLAUDE.md** — постоянные инструкции (читаются каждый раз)
2. **Memory** — долгосрочный контекст (agent-memory-mcp, Yodoca)
3. **MCP tools** — расширение возможностей агента
4. **Skills** — повторно используемые процедуры
5. **Rules** — ограничения и стиль ответов

## Почему важно для Lorenzo

Lorenzo — один из лучших примеров Context Engineering в русскоязычном OSS:
- `CLAUDE.md` — 500+ строк контекста проекта
- 12 MCP-серверов — расширение контекста через инструменты
- `docs/` — база знаний в контексте
- `.claude/skills/` — повторно используемые процедуры
- `improve_watcher.py` — автообновление контекста при изменениях

Статья даёт **теоретическую рамку** для того, что Lorenzo делает практически.
