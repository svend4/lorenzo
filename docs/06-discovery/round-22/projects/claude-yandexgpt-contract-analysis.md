**Уникальность:** Первый русскоязычный эксперимент: Claude vs YandexGPT на одном договоре поставки — Claude нашёл в 2.5× больше рисков. Причина: 200K контекст позволяет читать договор целиком (vs чанки), юридическое рассуждение распознаёт скрытые риски (1%/день = 365%/год). Паттерн: Claude как «второй юрист», YandexGPT — быстрый первичный анализ.

## Ключевой эксперимент

```
Один и тот же договор поставки →
  YandexGPT: нашёл N рисков
  Claude:     нашёл 2.5×N рисков

Разница в подходах:
  YandexGPT: чанкинг → анализ по частям → сводный список
  Claude: весь договор в 200K контекст → единый анализ → связи между статьями
```

## Конкретный пример: скрытый риск

```
Статья договора:
  "Пеня за просрочку: 1% от суммы за каждый день.
   Максимальный размер пени: 2% от суммы договора."

YandexGPT: видит cap 2% → "приемлемые условия"
           → риск НЕ отмечен

Claude: 1% в день = 30% в месяц = 365% годовых
        cap 2% = накопится за 2 дня
        → "Хищнические условия по ст. 333 ГК РФ: суд снизит,
           но сам факт наличия создаёт правовую неопределённость"
        → риск КРИТИЧЕСКИЙ
```

**Юридическое рассуждение**: Claude применяет правовые нормы (ст. 333 ГК РФ), а не только читает текст.

## Архитектура анализатора договоров

```
Договор (PDF/DOCX) → Docling/MarkItDown → чистый текст
        ↓
Этап 1: YandexGPT (быстрый scan, локально, дёшево)
  → первичный список рисков (базовые паттерны)
  → latency: ~3-5 секунд
        ↓
Этап 2: Claude (глубокий анализ, если риски найдены)
  → весь договор в контекст (до 200K токенов)
  → запрос: "Найди скрытые риски, связи между статьями, соответствие ГК РФ"
  → latency: ~15-30 секунд
        ↓
Этап 3: Ensemble merge
  → объединить уникальные риски из обоих
  → ранжировать по критичности: КРИТИЧЕСКИЙ / ВЫСОКИЙ / СРЕДНИЙ
  → structured output: JSON с цитатами из договора
        ↓
Юридический отчёт
```

## Типы рисков, которые ловит Claude (но не YandexGPT)

```
1. Связи между отдалёнными статьями
   "Статья 5.1 + Статья 12.4 вместе создают риск X"
   → YandexGPT читает чанками → не видит связей

2. Скрытые вычисления
   "1% в день = 365% годовых" (нужна арифметика)
   "Срок 30 банковских дней = ~45 календарных"

3. Правовые ссылки
   "Это противоречит ст. 782 ГК РФ об одностороннем отказе"
   "По ст. 421 ГК РФ эта формулировка уязвима"

4. Асимметрия прав
   "Поставщик может расторгнуть за 3 дня, покупатель — за 30"
   (разные статьи → нужен полный контекст)
```

## Промпт для анализа рисков

```python
RISK_ANALYSIS_PROMPT = """
Ты — опытный юрист по договорному праву России.
Проанализируй договор поставки и найди ВСЕ риски.

## Договор:
{full_contract_text}

## Найди:
1. КРИТИЧЕСКИЕ риски (нарушают ГК РФ, могут обнулить договор)
2. ВЫСОКИЕ риски (создают значительные финансовые потери)
3. СРЕДНИЕ риски (нежелательные условия, но приемлемые)

Для каждого риска:
- Цитата из договора
- Почему это риск
- Правовая норма (статья ГК РФ / ФЗ)
- Рекомендация по исправлению

Отвечай в JSON:
{{risks: [{{level, quote, reason, law, recommendation}}]}}
"""
```

## Ensemble vs Single Model

| Подход | Найдено рисков | Стоимость | Latency |
|--------|---------------|-----------|---------|
| Только YandexGPT | 100% baseline | дёшево (RU API) | 5 сек |
| Только Claude | 150% baseline | дороже | 25 сек |
| **Ensemble** | **250% baseline** | средне (YandexGPT + Claude) | 30 сек |

Оптимальная стратегия: сначала YandexGPT, потом Claude только для договоров >1M рублей.

## Применение к Lorenzo

Lorenzo анализирует документы из `docs/`.  
Contract Analysis паттерн = Document Risk Analysis:

```python
# improve_doc_risk.py (паттерн):
def analyze_doc_risks(file_path: str) -> RiskReport:
    text = read_doc(file_path)  # Docling если PDF

    # Быстрый scan (Haiku = дёшево)
    quick_risks = haiku_client.quick_scan(text)

    if quick_risks.severity > THRESHOLD:
        # Глубокий анализ (Opus с full context)
        deep_risks = opus_client.deep_analysis(text, quick_risks)
        return merge_risks(quick_risks, deep_risks)

    return quick_risks
```
