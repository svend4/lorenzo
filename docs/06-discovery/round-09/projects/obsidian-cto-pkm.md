Структура PARA (Проекты / Сферы / Ресурсы / Архив). **Явный паттерн:** что публиковать и что никогда не публиковать. Применимо к Lorenzo как к базовой PKM-схеме поверх Obsidian-vault.

## Стек

| Инструмент | Роль |
|------------|------|
| Obsidian | Основное хранилище (локально) |
| Dataview | Запросы по заметкам (SQL-like) |
| Templater | Шаблоны для заметок |
| Omnisearch | Полнотекстовый поиск внутри Obsidian |
| Git | Версионирование vault |

## Структура PARA

```
00. Входящие/      — инбокс, попадает всё
01. Проекты/       — активные проекты с дедлайном
02. Сферы/         — постоянные обязанности (DevSecOps, CS...)
03. Ресурсы/       — референсные материалы
04. Архив/         — завершённые проекты
05. Дневник/       — ежедневные записи
```

## Правило публичности

Никогда не публично: рабочие детали с конкретными системами, личные записи, инциденты.  
Всегда публично: принципы, паттерны, обезличенные выводы.

## Почему важно для Svyazi

Lorenzo уже имеет `improve_obsidian.py` (YAML frontmatter + wikilinks).  
Эта схема — конкретный рецепт PARA-структуры поверх Lorenzo-corpus для Obsidian.  
Позволяет сделать Lorenzo-vault одновременно PKM-системой CTO и knowledge base проекта.

## Возможные комбинации

| Комбинация | Новое свойство |
|------------|----------------|
| **PARA + improve_obsidian** | Lorenzo-карточки в PARA-структуре → Obsidian PKM из коробки |
| **PARA + Flashcard SaaS (R08)** | Ресурсы из PARA → учебные флешкарты автоматически |
| **PARA + improve_digest_auto** | Дайджест изменений → Дневник в PARA структуре |
| **PARA + SocratiCode (R08)** | Код → Проекты/Сферы PARA, документы → Ресурсы |
