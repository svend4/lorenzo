**Уникальность:** Открытая спецификация для **децентрализованной когнитивной сети AI-агентов**: без центрального оркестратора, агенты самоорганизуются через P2P (DHT), согласовывают знания через голосование, фильтруют неэтичные решения. Это прямая альтернатива паттерну «один оркестратор → N агентов» из всех предыдущих раундов.

## Архитектура HMP (4 компонента)

| Компонент | Роль |
|-----------|------|
| **Cognitive Core** | Автономный агент с REPL-циклом и когнитивной памятью |
| **Cognitive Shell** | Исполнитель команд для внешнего AI без автономного мышления |
| **MeshNode** | P2P-модуль с DHT и синхронизацией |
| **Enlightener** | Этический модуль: фильтрация и аудит решений |

## Протокольные слои

- **Trust Layer** — агенты формируют доверительные отношения
- **Consensus Layer** — децентрализованное голосование по обновлениям знаний
- **Ethical Governance Protocol** — защита от неэтичных решений
- **Goal Management Protocol** — совместное планирование и исполнение

## Ключевой тезис

> Будущее AI-агентов — децентрализованные сети, а не оркестраторы.

HMP v5.0 — полностью переработанная спецификация, несовместимая с v4.x.  
Цель: зрелая модель без накопленных компромиссов.

## Почему важно для Svyazi

Все раунды R01–R08 строятся вокруг паттерна «оркестратор → агенты».  
HMP — альтернатива: агенты равноправны, консенсус через голосование, нет SPOF.  
Применимо как долгосрочная архитектура Svyazi, когда нужна устойчивость к сбоям.

## Возможные комбинации

| Комбинация | Новое свойство |
|------------|----------------|
| **HMP + TRAIL spec (R04)** | TRAIL = MCP-пайплайн внутри узла, HMP = между узлами |
| **HMP + openLight (R07)** | openLight skills + HMP consensus → распределённая инфра |
| **HMP + News System (R05)** | 5 агентов новостей → HMP mesh без центрального оркестратора |
| **HMP + MCP4 протокол (R07)** | MCP внутри узлов, HMP между узлами — полная иерархия |
