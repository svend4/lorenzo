## Проблема: нормоконтроль = узкое горлышко

```
Что такое нормоконтроль:
  Проверка документа на соответствие:
  → правилам русского языка (грамматика, пунктуация, стилистика)
  → внутренним корпоративным стандартам (формулировки, аббревиатуры)
  → отраслевым нормам (ГОСТ, ОСТ, СТО)

Боли:
  1-2 специалиста = bottleneck при большом объёме
  Субъективность: разные проверяющие — разные правки
  Усталость: одни и те же ошибки пропускаются в конце дня
  Низкая скорость: очередь документов растёт

Масштаб на крупном предприятии:
  500-2000 документов/день (приказы, протоколы, служебные записки)
  → нормоконтролёр физически не успевает
```

## Архитектура в Directum RX

```
Документ (в Directum RX) → Trigg on status change
      ↓
LLM Normcontrol Service
  ├── RAG: Корпоративные правила (регламент, стандарты)
  │     → "Слово 'руководитель' пишется строчными"
  │     → "Дата в формате ДД.ММ.ГГГГ без слова 'года'"
  │     → "Нельзя использовать аббревиатуры без расшифровки"
  │
  ├── LLM (open-source, on-premise):
  │     → Qwen/GigaChat/Llama — на выбор
  │     → Промпт: "Проверь документ согласно правилам из [RAG context]"
  │
  └── Structured Output:
        → список замечаний с цитатой и рекомендацией
        → severity: CRITICAL / WARNING / INFO
              ↓
Directum RX: замечания отображаются автору документа
  → автор исправляет → повторная проверка
  → нормоконтролёр видит только спорные случаи
```

## Промпт нормоконтроля

```python
NORMCONTROL_PROMPT = """
Ты — эксперт по деловому русскому языку и документообороту.
Проверь документ на соответствие правилам.

## Корпоративные стандарты:
{corporate_rules_from_rag}

## Общие правила русского делового языка:
- Деловой стиль: нейтральный тон, без эмоций
- Даты: формат ДД.ММ.ГГГГ или «01 января 2026 г.»
- Аббревиатуры: первое употребление — с расшифровкой
- Должности и звания: строчными буквами, кроме начала предложения
- Числа: прописью в юридических и финансовых текстах до тысячи

## Документ для проверки:
{document_text}

## Задача:
Найди ВСЕ несоответствия. Для каждого:
1. Цитата из документа (точная)
2. Нарушенное правило
3. Рекомендация по исправлению
4. Уровень: КРИТИЧНО (документ недействителен) / ЗАМЕЧАНИЕ / УЛУЧШЕНИЕ

JSON: [{{"quote": "...", "rule": "...", "fix": "...", "severity": "..."}}]
Если замечаний нет — вернуть пустой массив [].
"""
```

## Два режима: проверка vs сравнение редакций

```python
# Режим 1: Нормоконтроль нового документа
def check_document(text: str) -> list[NormIssue]:
    rules = rag.get_relevant_rules(text)
    return llm.check(text, rules)

# Режим 2: Сравнение редакций договора (статья 990044)
# "Найди 10 отличий" — смежная статья Directum
def compare_versions(v1: str, v2: str) -> DiffReport:
    """Найти смысловые изменения между версиями документа"""
    return llm.compare(
        old_version=v1,
        new_version=v2,
        focus=["добавленные обязательства", "изменённые сроки",
               "новые условия", "удалённые пункты"]
    )
    # Не pixel diff — смысловой diff через LLM
    # "В пункте 4.2 изменён срок оплаты с 30 на 14 дней"
```

## LLM как "знаток организации"

```python
# Ключевое: LLM знает внутренние правила конкретной организации
# Не только общие правила языка — но и специфику компании

class OrganizationKnowledgeBase:
    """RAG из внутренних регламентов организации"""

    def load_corporate_docs(self, org_id: str):
        # Загрузить регламенты этой конкретной организации:
        self.index([
            "Стандарт оформления служебных записок v3.2.pdf",
            "Регламент делопроизводства 2025.docx",
            "Словарь принятых сокращений.xlsx",
            "Типовые формулировки для приказов.md"
        ])

    def get_rules(self, doc_type: str) -> list[str]:
        """Вернуть правила для конкретного типа документа"""
        return self.vector_search(f"правила {doc_type}")

# Разные организации → разные правила → один LLM
# Multi-tenant: каждый клиент Directum имеет свой корпоративный RAG
```

## Метрики внедрения

```
Проблема baseline (ручной нормоконтроль):
  Пропущено ошибок: ~20% (субъективность + усталость)
  Время на документ: 8-15 минут
  Очередь в пиковый период: 3-5 дней

После внедрения LLM нормоконтроля:
  Пропущено ошибок: ~3% (LLM устаёт иначе чем человек)
  Время: ~25 секунд (API call)
  Очередь: нет (мгновенная проверка)
  Нагрузка на нормоконтролёра: -80% (только спорные случаи)
  Единообразие: 100% (одинаковые правила для всех)
```

## Применение к Lorenzo

Lorenzo имеет `improve_spellcheck.py` и `improve_validate.py`.  
Normcontrol паттерн = **Structured Document QA** по корпоративным стандартам:

```python
# improve_normcontrol.py (паттерн):
LORENZO_STYLE_RULES = """
Правила для файлов docs/06-discovery/:
- Каждый проект-файл должен содержать секции: Автор, Слой, Дата, Уникальность
- Ниша файла должна соответствовать заголовку секции
- Применение к Lorenzo — обязательная секция
- Возможные комбинации — минимум 3 строки
"""

def check_discovery_file(file_path: str) -> list[Issue]:
    content = read_file(file_path)
    return llm.check_against_rules(content, LORENZO_STYLE_RULES)
# Применение: автоматически проверять новые discovery-файлы на полноту
```

## Возможные комбинации

| Комбинация | Новое свойство |
|------------|----------------|
| **Нормоконтроль + Legal RAG (R25)** | Проверка по корпоративным правилам + судебная практика = полный legal check |
| **Нормоконтроль + Contract Analysis (R22)** | Нормоконтроль стиля → Claude анализирует риски = двухэтапная проверка договора |
