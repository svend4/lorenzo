## Задача и результат

```
До внедрения:
  Отдел обработки возвратов: 5 операторов
  Среднее время обработки: 42 минуты
  Ручная работа: проверить заявку → 1С → email поставщику → статус → закрыть

После внедрения (3 агента):
  Операторов: 5 → 2 (исключения и сложные случаи)
  Среднее время: 42 мин → 6 мин (-85%)
  Нагрузка на операторов: -80% (рутина уходит к агентам)
  Метрика "цель не в 100% автоматизации, а в 20% рутины для человека"
```

## Архитектура трёх агентов

```
Входящая заявка на возврат
        ↓
Agent 1: Classifier (анализирует заявку)
  → определяет тип возврата (брак / ошибка заказа / не тот товар)
  → извлекает данные: артикул, количество, контрагент
  → tool_use: поиск в 1С по артикулу
        ↓
Agent 2: Processor (выполняет операцию)
  → tool_use: создать документ возврата в 1С
  → tool_use: отправить email поставщику (шаблон + данные)
  → tool_use: обновить статус заявки в CRM
  → если ошибка → Human In Loop (передать оператору с контекстом)
        ↓
Agent 3: Monitor (контроль и эскалация)
  → отслеживает статусы: поставщик ответил?
  → если нет ответа 24ч → повторный запрос
  → если нет 72ч → эскалация оператору с историей
        ↓
Решено / Передано оператору (только исключения)
```

## Ключевые инсайты из кейса

### 1. Инструменты > параметры модели

```
НЕ: «возьмём GPT-5, он умнее»
ДА: «дадим агенту доступ к 1С, email, CRM»

Агент с qwen2.5:7b + API 1С > GPT-5 без интеграций
(для этой конкретной задачи)
```

### 2. Human in Loop — не провал, а цель

```
Целевая архитектура:
  80% задач → полностью автоматически
  20% задач → агент готовит контекст, человек принимает решение

Human in Loop — это не фолбэк, это intended behavior.
Операторы занимаются только реальными исключениями.
```

### 3. Process Map первичен

```
Процесс проектирования:
  Шаг 1: Нарисовать процессную карту (BPMN)
  Шаг 2: Определить роли агентов (по зонам ответственности)
  Шаг 3: Подобрать инструменты (API, tools)
  Шаг 4: Выбрать модели (последнее!)

НЕ: «возьмём LangChain и посмотрим»
ДА: «вот процесс, вот агенты, вот инструменты, потом — модель»
```

### 4. Интеграции через адаптеры

```python
# Интеграция с 1С без изменения исходного кода 1С:
class OneC_Adapter:
    def search_item(self, article: str) -> ItemInfo:
        # REST API 1С OData — стандартный протокол
        return self._api.get(f"/odata/Catalog_Items?$filter=Code eq '{article}'")
    
    def create_return_doc(self, doc: ReturnDoc) -> str:
        return self._api.post("/odata/Document_ReturnToVendor", doc.to_dict())
```

## Возможные комбинации

| Комбинация | Новое свойство |
|------------|----------------|
| **3-агент паттерн + A2A (R21)** | A2A протокол координирует агентов независимо от фреймворка |
| **3-агент + Langfuse (R13)** | Каждое действие агента трейсится → видна эффективность Human in Loop |
