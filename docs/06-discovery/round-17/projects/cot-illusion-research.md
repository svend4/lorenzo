# CoT Illusion — LLM-агенты игнорируют факты, CoT делает хуже

**Автор:** независимый исследователь (Хабр, апрель 2026)  
**Хабр:** https://habr.com/ru/articles/1020016/  
**GitHub:** нет (экспериментальная статья с воспроизводимыми тестами)  
**Слой:** orchestration / quality / research  
**Дата:** апрель 2026  
**Уникальность:** Контрарианское исследование: автор экспериментально доказал, что в agent loop (Prompt → Tool Call → Reading → Answer) **LLM игнорирует факты из контекста**, а Chain-of-Thought **ухудшает** результат в ряде задач. Первая русскоязычная статья с систематическим опровержением популярного приёма.

## Ключевые находки

### Паттерн который не работает как ожидается

```
Каждый второй стартап строит так:
Prompt → Tool Call (API / поиск) → Чтение результата → Ответ
         ↑
Ожидание: LLM самостоятельно расследует и находит баги.
Реальность: LLM игнорирует факты и галлюцинирует "поверх" контекста.
```

### Почему CoT ухудшает

1. **CoT увеличивает уверенность модели** — агент "обосновывает" неверный ответ вместо его пересмотра
2. **Reasoning trace ≠ reasoning** — красивая цепочка мыслей ≠ правильное рассуждение
3. **Накопление ошибок** — длинная CoT-цепочка аккумулирует ошибки
4. **Context dilution** — факты "тонут" в собственных рассуждениях модели

### Когда CoT помогает

| Задача | CoT полезен | CoT не нужен / вреден |
|--------|------------|----------------------|
| Математика, логика | ✅ | |
| Анализ фактических данных из контекста | | ❌ чаще вредит |
| Кодогенерация | ✅ (план → код) | |
| Tool-use агент с реальными данными | | ❌ маскирует ошибки |

## Практические выводы (из статьи)

1. **Верифицируй факты структурно**, не через CoT:  
   вместо "подумай шаг за шагом" → заставь модель выписать цитаты из контекста
2. **Constraint prompting** эффективнее CoT для фактических задач
3. **Self-consistency** (несколько ответов → голосование) > long CoT
4. **RAG + structured extraction** > RAG + free CoT
