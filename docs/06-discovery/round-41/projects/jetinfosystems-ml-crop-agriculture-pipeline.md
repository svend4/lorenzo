Честная документация производственных проблем: облачность над полями, редкость метеостанций, ошибки ввода от полевых работников.

## Проблема: агрономы не успевают за тысячами гектаров

```
Агрохолдинг: тысячи гектаров с десятками культур
  → Агроном должен решить: "Когда объезжать поля?"
  → Ручной мониторинг: невозможно охватить всё
  → Традиционное решение: фиксированные даты + интуиция

Данные есть, но разрозненные:
  → Спутниковые снимки Sentinel-2 (NDVI-индекс вегетации)
  → Метеостанции (температура, осадки, влажность почвы)
  → Экспертные отчёты агрономов (ретроспективные)
  → Нет единого источника истины для прогноза

ML-решение Jet Infosystems:
  → 8-этапный Airflow-пайплайн интеграции источников
  → ML-модели, сезонно переобучаемые на актуальных данных
  → Формулы агрономических норм + data-driven коррекция
  → Grafana-дашборды + ручные override для агрономов
```

## Ключевые паттерны для Lorenzo

```python
class LorenzoAgroPattern:
    """
    Jet Infosystems паттерн для Lorenzo:
    Гибрид domain-expert rules + ML-коррекция.
    Сезонное переобучение = актуализация по новым данным.
    """

    # Паттерн 1: Domain rules + ML correction
    def predict_with_rules(self, raw_features: dict,
                            domain_formula_result: float) -> float:
        """
        1. Применить детерминированную формулу (агроном знает больше LLM)
        2. ML-модель: обучена на отклонениях реального vs формульного
        3. Итог = формула + ML-дельта
        """
        ml_correction = self.model.predict(raw_features)
        return domain_formula_result + ml_correction

    # Паттерн 2: Human override всегда приоритетнее ML
    def apply_human_override(self, prediction: float,
                              manual_value: float | None) -> float:
        """
        Агроном всегда прав: если есть ручное значение → использовать его.
        ML — помощник, не замена эксперту.
        """
        return manual_value if manual_value is not None else prediction
```
