## Ключевая идея

> Традиционный BI: пользователь открывает дашборд, смотрит на цифры, думает сам.  
> BI-агент: пользователь задаёт вопрос → агент возвращает анализ + источники + рекомендации + действия.

Переход от **пассивного наблюдения** к **активному ответу**.

## Архитектурный паттерн

```
Вопрос пользователя (natural language)
        ↓
Text-to-SQL агент
        ↓
SQL-запрос с семантическим контекстом (описания таблиц/колонок)
        ↓
Результат + анализ + рекомендации + action items
        ↓
Пользователь
```

### Критическое условие

**Семантический контекст** таблиц и колонок обязателен:
- `revenue` → "выручка в рублях без НДС, за текущий месяц"
- `user_id` → "уникальный идентификатор клиента, не путать с session_id"

Без контекста Text-to-SQL агент делает ошибки на реальных схемах.

## Технические компоненты (из статьи)

| Компонент | Назначение |
|-----------|-----------|
| Text-to-SQL LLM | перевод вопроса в запрос |
| Metadata store | таблицы + описания колонок |
| Query executor | безопасный запуск SQL |
| Interpretation layer | интерпретация + рекомендации |
| Action layer | опционально: выполнение действий |

## Почему важно для Svyazi

METRICS.md, HEALTH.md, KPI.md — это статичные дашборды Lorenzo.  
BI Agent Pattern показывает следующий уровень: **агент отвечает на вопросы о метриках**,  
а не просто рендерит цифры в Markdown.  
`improve_llm_qa.py` + семантический контекст метрик = прообраз BI-агента над Lorenzo.

## Возможные комбинации

| Комбинация | Новое свойство |
|------------|----------------|
| **BI Pattern + improve_llm_qa.py** | QA-агент над метриками Lorenzo (HEALTH, KPI, METRICS) |
