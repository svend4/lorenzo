## Структура серии

### Часть 1 — Идея и датасет (1033128)
- Зачем учить свою LLM для мониторинга
- Сбор трейсов нормального и аномального поведения
- Формат датасета: `{context, query, expected_response}`

### Часть 2 — Обучение (1033426)
- Fine-tuning (LoRA/QLoRA) базовой модели
- Проблема: delta-merge не подходит → fresh-from-base подход
- Нехватка трейсов → аугментация данных

### Часть 3 — Дистилляция (1033434)
- Дистилляция от большой модели (учитель) в маленькую (ученик)
- Скрипт `distill.py` в репозитории
- Бенчмарк `run_benchmark.py` для оценки качества
- Воспроизводимость: документированный формат датасета

## Ключевой паттерн

```
Большая LLM (учитель, например Claude / GPT)
  генерирует "правильные" ответы на примеры мониторинга
        ↓
Датасет: {аномалия → диагноз + действие}
        ↓
Маленькая LLM (ученик, 7B QLoRA)
  обучается воспроизводить ответы учителя
        ↓
Специализированный мониторинг-агент (fast, local, cheap)
```

## Почему важно для Svyazi

Это прямой рецепт для Lorenzo:
1. Сгенерировать датасет из `audit.db` (нормальные и аномальные паттерны MCP-вызовов)
2. Дистиллировать в Qwen 2.5 7B через Claude (Anthropic API = учитель)
3. Получить локальный fast-агент для мониторинга без облака

Объединяет: Fine-tuning 2026 (R15) + Observability (R13) + audit.db Lorenzo.

## Возможные комбинации

| Комбинация | Новое свойство |
|------------|----------------|
| **Custom LLM + audit.db Lorenzo** | Дистиллировать из audit.db паттерны → мониторинг-агент знает Lorenzo |
| **Custom LLM + Fine-tuning 2026 (R15)** | R15 даёт инструменты (Unsloth) → эта серия даёт датасет-паттерн |
| **Custom LLM + Observability (R13)** | Langfuse собирает трейсы → Custom LLM дистиллирует по ним |
| **Custom LLM + DSPy (R14)** | DSPy оптимизирует промпты учителя → лучший датасет для дистилляции |
