## Почему LangChain ломается в production

| Обещание LangChain | Реальность |
|-------------------|-----------|
| Абстракция провайдера (смена OpenAI → Anthropic = 1 строка) | Поведение становится непредсказуемым после смены |
| Цепочки упрощают логику | Сложная отладка: ошибка скрыта в 3 слоях абстракций |
| Готовые инструменты | Версии инструментов конфликтуют между собой |
| Хорошо для прототипов | Технический долг при росте системы |

### Вывод автора

> «LangChain отлично для PoC и демо инвесторам.  
>  Для production — строите на фреймворке, не контролируя его».

## Архитектура без LangChain

```
Входящее сообщение (Telegram / WhatsApp / Max)
        ↓
Router Agent (классифицирует тип запроса)
  ├── "жалоба" → Complaint Agent
  ├── "вопрос" → FAQ Agent (RAG)
  └── "действие" → Action Agent (CRM API)
        ↓
Orchestrator (чистый Python dict/dataclass, без фреймворка)
        ↓
LLM вызов (прямой SDK: openai / anthropic / gigachat)
        ↓
Ответ пользователю
```

### Ключевые принципы

1. **Агент = функция**: принимает state dict, возвращает state dict
2. **Граф = Python**: `{node: [next_nodes]}` — прозрачный роутинг
3. **LLM = прямой SDK**: без обёрток, контроль над каждым вызовом
4. **State = dataclass**: типизированное состояние системы

## Применение к Lorenzo

`improve_run_all.py` — оркестратор 159 скриптов.  
`improve_workflow_v2.py` — workflow engine v2.  
Паттерн из статьи: заменить YAML-workflow на **Python-граф агентов**:  
каждый `improve_*.py` = узел графа, переходы по результату предыдущего.

Это делает workflow debugging в 10× проще: каждый шаг — обычная Python-функция.

## Возможные комбинации

| Комбинация | Новое свойство |
|------------|----------------|
| **No-LC + improve_workflow_v2** | Python-граф заменяет YAML: типизированный, тестируемый, отлаживаемый |
| **No-LC + openLight (R07)** | openLight whitelist + Python-граф = полностью предсказуемый агент |
| **No-LC + Observability (R13)** | Прямые SDK-вызовы трейсятся в Langfuse без обёрточного шума |
| **No-LC + ADD (R13)** | Граф-агент с ADD feedback loop — проще добавить eval-узел |
