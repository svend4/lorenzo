> Скрипты, которые читают другие скрипты и документы — и улучшают их.

## Как это называется

У этого подхода несколько имён в зависимости от контекста:

| Термин | Смысл |
|--------|-------|
| **Метапрограммирование** | программа, которая анализирует и генерирует другие программы |
| **Интроспекция кодовой базы** | скрипт читает сам себя и соседей, понимает структуру |
| **Самообогащение** | на основе прочитанного улучшает себя и других |
| **Бутстрэппинг** | используй существующие паттерны чтобы породить новые |
| **Code synthesis** | синтез нового кода из анализа старого |
| **Рефлексивный агент** | агент, который думает о своих собственных инструментах |

В проекте Lorenzo это можно назвать **«скрипт четвёртого порядка»**:

```
Порядок 1: скрипт читает docs/        → improve_health.py
Порядок 2: скрипт читает скрипты      → improve_dependency_map.py
Порядок 3: скрипт улучшает скрипты    → [новое]
Порядок 4: скрипт порождает скрипты   → [новое]
```

---

## Зачем это нужно

Сейчас 155 скриптов. Никто не держит в голове:
- что каждый из них делает
- какие входы и выходы у каждого
- какие скрипты дублируют друг друга
- каких скриптов не хватает
- какой документации нет

Метаскрипт читает всё это автоматически и может:
1. **Аудировать** — «вот что есть, вот чего нет»
2. **Обогащать** — добавить docstring, типизацию, примеры
3. **Синтезировать** — создать новый скрипт по шаблону
4. **Соединять** — найти скрипты которые должны вызывать друг друга

## Три кита: Чтение → Понимание → Действие

```
ЧТО ЧИТАЕМ              КАК ПОНИМАЕМ           ЧТО ДЕЛАЕМ
────────────────         ─────────────          ──────────────
scripts/*.py     →  AST-разбор          →  карта функций
                    docstring-анализ        карта зависимостей
                    import-граф             пробелы в покрытии

docs/**/*.md     →  заголовки H2/H3     →  темы без скриптов
                    упоминания скриптов     скрипты без доков
                    TODO/FIXME

CLAUDE.md        →  описания скриптов   →  несоответствия
                    группы и порядки        устаревшие записи
```

## Граница: что скрипт может делать сам, что — только с LLM

```
БЕЗ LLM (детерминировано, бесплатно):
  ✅ Прочитать docstring каждого скрипта
  ✅ Построить граф импортов
  ✅ Найти скрипты без docstring
  ✅ Найти дубли (похожие функции)
  ✅ Найти упоминания в docs/ без соответствующего скрипта
  ✅ Сгенерировать скрипт по шаблону (заполнить форму)

С LLM (claude-haiku, ~$0.001/скрипт):
  ✅ Написать осмысленный docstring
  ✅ Понять что скрипт делает «по смыслу»
  ✅ Предложить улучшения логики
  ✅ Написать новый скрипт «с нуля» под задачу
  ✅ Найти противоречия между тем что скрипт обещает и делает
```
